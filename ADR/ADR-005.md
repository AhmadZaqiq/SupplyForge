# ADR-005: Document numbering and sequence generation

- **Status:** Accepted (product owner, 2026-11-16) — reconstructed from PRD v0.8 with recommendation defaults approved
- **Date:** 2026-11-16
- **Deciders:** Product owner (accepted 2026-11-16); mechanism text recovered from PRD D-15, PLT-073, PLT-073a…e, NFR-043 item 9, `06b` §6.4.4
- **PRD references:** D-15; PLT-073, PLT-073a…e; DM-3; shared table `DocumentSequence` (MOD-1a); NFR-012

## Context

NFR-043 marks document numbering (D-15) as **DONE: ADR-005** but the file was missing. The PRD requires per-type patterns, optional branch/fiscal segments, DB-unique concurrent-safe generation, **gaps allowed**, and no reuse of voided numbers. PLT-073b explicitly defers uniqueness mechanics to an ADR.

## Decision Drivers

- D-15: per type + optional branch/fiscal; **gaps allowed**
- PLT-073a: pattern e.g. `PO-{yyyy}-{branch?}-{seq}`
- PLT-073b: uniqueness via DB unique constraint + concurrent-safe generation
- PLT-073c: no gapless promise without legal requirement (none demonstrated)
- PLT-073d: voided numbers not reused
- MOD-1a: `DocumentSequence` is shared infrastructure written via interfaces
- DM-3: surrogate keys BIGINT; human numbers are **displayed** numbers
- NFR-012: critical invariants DB-constrained where practical

## Options Considered

### Option A: Gapless per-day counters with application-level locking only
Pros: pretty numbers. Cons: violates PLT-073c spirit under failure; higher deadlock risk; PRD explicitly allows gaps.

### Option B: Database sequence / counter row + unique constraint on issued number **(chosen)**
Pros: concurrent-safe; matches PLT-073b; gaps natural on rollback; simple. Cons: gaps in display numbers (accepted by PRD).

### Option C: UUID/GUID as human document number
Pros: trivial uniqueness. Cons: unusable as operational document numbers (PRD examples are patterned).

## Decision

### PRD-confirmed

1. **Pattern per document type** (PLT-073a), example: `PO-{yyyy}-{branch?}-{seq}` where `{branch?}` and fiscal segments follow **D-15** (optional per type).
2. **Display number ≠ surrogate key** (DM-3): rows still use BIGINT ids; document number is a unique business attribute.
3. **Uniqueness:** DB **unique constraint** on the issued number (per scope implied by pattern—see recommendation) plus **concurrent-safe generation** (PLT-073b).
4. **Gaps allowed** on void/cancel or sequence reserve failure (PLT-073c). **No gapless numbering** promise.
5. **Voided numbers are never reused** (PLT-073d).
6. **Storage:** `DocumentSequence` shared table; access only via Platform Core / infrastructure interface (MOD-1a)—modules do not own raw sequence tables.
7. **Fiscal-year rollover** configurable is **P2** (PLT-073e)—not in A0/A1 scope beyond leaving the pattern data-driven.

### Recommendation — requires owner approval

| Choice | Recommendation | Why |
|---|---|---|
| Sequence allocation | `UPDATE ... SET NextValue = NextValue + 1 OUTPUT inserted.NextValue` (or equivalent atomic increment) under the ambient transaction (ADR-003) | Concurrent-safe without app locks |
| Scope of uniqueness | Unique on `(DocumentType, PatternScope, Year, BranchSegment, Seq)` matching the rendered pattern—not a global seq across types | Matches per-type patterns |
| Sequence row granularity | One row per (type, year, branch-or-global) | Simple; gaps only when TXN rolls back after reserve |
| Rendered number format | Zero-pad `seq` to fixed width per type (recommend 6) for sort stability | Presentation only; not PRD text |
| When number is assigned | At document **creation** (draft), not at post; void keeps the number burned | PLT-073d |

Zero-pad width and exact uniqueness key columns are **recommendations**—approve before first migration that creates `DocumentSequence`.

## Consequences

- **Positive:** Safe under concurrency; testable with parallel allocate tests; aligns D-15.
- **Negative:** Operators may see gaps; must document “gaps allowed” in UI/runbook.
- **Follow-up:** Numbering tests `PLT-073*` / `PLT-073b_*` with parallel tasks; A1 starts using patterns for real docs.

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Sequence row contention hot spot | Per-type rows; short TXNs; acceptable at P1 scale (G-8) |
| Double-render same number | Unique constraint is the backstop; retry on violation |
| Pattern change mid-year | New ADR + migration; old numbers immutable |

## Reassessment

If a jurisdiction ever requires gapless numbers (none in scope—A-10 portfolio), supersede with a legal-compliant design. Before B2 if fiscal reset (PLT-073e) becomes P1.
